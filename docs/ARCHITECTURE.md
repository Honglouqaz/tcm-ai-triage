# 架构说明

## 分层

| 层 | 位置 | 职责 |
|---|---|---|
| 规则数据 | `rules/*.json` | 体质 / 证型 / 症状 / 中药 / 方剂 / 化验指标 |
| 推理引擎 | `src/worker/constitution.js`、`lab_analysis.js`、`ai_diagnose.js` | 打分、匹配、解释生成 |
| 路由层 | `src/worker/tcm_worker_v3.js`、`handlers.js` | 边缘函数入口、KV 读取、可选 LLM 调用 |
| 前端 | `src/web/index.html` | 单页应用，零依赖 |
| 数据构建 | `tools/build_constitution.py`、`vectorize_tcm.py` | 从教材文本生成结构化规则 / 向量索引 |

## 几个设计选择

1. **规则优先，模型兜底**：先跑规则，规则拿不准才调 LLM；LLM 只负责「把话说明白」，
   不让它决定「是什么证」。这样结果可复现、可审计。
2. **证型打分分层**：主症命中权重 > 次症 > 舌脉，避免「一个舌象压过一堆主诉」。
3. **同义词归一前置**：用户说「睡不好」「翻来覆去」「入睡困难」都归到同一节点，
   否则规则命中率会被口语表达打散。
4. **不做疾病诊断**：化验指标只给参考区间与关联线索，结论交回医师。
5. **数据与代码分离**：`rules/` 全 JSON，换教材口径不用改一行代码。
